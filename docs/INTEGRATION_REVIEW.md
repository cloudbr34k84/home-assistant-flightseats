# FlightSeats integration review

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

Reviewed 7 November 2026 against the HA Integration Dev skill and Home Assistant 2026.11.0.

## Findings and changes

- Raised HACS minimum from 2025.3.0 to 2026.8.0: the existing `DeviceInfo.via_device_id` API landed in 2026.8. This corrects an unsupported compatibility claim; it does not change stored entries or entity IDs.
- Replaced the superseded custom-component test package with pinned `pytest-homeassistant==2026.11.0`; updated test imports and added pinned Ruff development tooling.
- Reject nonfinite, negative, fractional seat/points and invalid reward flag fare data. Reject malformed nested flight collections. Sensor attributes cannot receive NaN/Infinity through these API values.
- Strip arbitrary remote error bodies and connection exception text from public API errors, preventing reflected credentials from reaching coordinator/action logs. Key-validation logging no longer includes tracebacks.
- Check watch expiry before reusing cached data; normalize old naive cache timestamps to UTC.
- Recover the daily quota after UTC midnight when the server omitted its reset header.
- Validate numeric watch inputs before conversion (whole numbers, finite values and allowed bounds), validate supported selections and dates, and reject empty program lists or reversed/past action date windows before consuming quota.
- Redact route/date configuration and omit watch titles in diagnostics, in addition to redacting API keys. Tolerate malformed top-level storage sections and watch containers.
- Updated GitHub workflow actions, explicit read permissions, timeouts, manual dispatch and disabled persisted checkout credentials. Added CI lint/format checks.
- Corrected development instructions: the installed integration is a separate copy, not the documented symlink. No live files were deployed or HA reloads requested.

## Current release compatibility

[Device registry changes](https://developers.home-assistant.io/blog/2026/07/21/device-registry-single-config-entry) justify the corrected minimum. Existing device info already uses the new API.

[Probatio](https://developers.home-assistant.io/blog/2026/09/30/probatio-validation-engine) retains `import voluptuous` compatibility for custom integrations; keeping it supports older HA releases.

[Entity lifecycle changes](https://developers.home-assistant.io/blog/2026/10/12/new-entity-lifecycle-hooks) retain a rename fallback until 2027.11 for custom entities overriding add/remove hooks. FlightSeats remains supported. Adopting `async_entity_id_changed` is future maintenance work; it is not required for 2026.11 and would need care to preserve 2026.8 support.
